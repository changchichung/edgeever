做 EdgeEver，不是因爲世界上缺一個筆記應用。

恰恰相反，筆記應用太多了。輕量的、重型的、協作優先的、Markdown 優先的、白板式的、數據庫式的，每一種都有自己的擁護者。但長期使用筆記軟件的人心裏大概都知道：真正難替代的並不是某個功能，而是一套已經長進肌肉記憶裏的工作流。

對我來說，這套工作流很接近經典印象筆記：左邊是筆記本樹，中間是筆記列表，右邊是正在寫的內容。打開、搜索、歸類、移動、繼續編輯，所有動作都應該足夠直接。它不需要每一步都顯得很酷，它需要穩定、清楚、快，並且讓我放心把多年積累的內容放進去。

但這幾年，我越來越難從現有產品裏得到這種放心。

---

### 我想要的是一個可靠的個人知識庫

很多人並不是要一個越來越龐大的效率平臺。我們只是想要一個可靠的個人知識庫：

- 能快速記錄和整理日常資料
- 能按熟悉的筆記本層級管理內容
- 能保存圖片、附件、富文本和長文
- 能在電腦和手機上都順手使用
- 能在需要時把數據拿出來

這些需求並不花哨，但它們很基礎。基礎能力一旦不穩定，筆記軟件就會從工具變成負擔。

我曾經喜歡印象筆記的原因，也正是因爲它在很長一段時間裏把這些基礎能力做得足夠好。三欄佈局、筆記本、搜索、跨設備同步，這些東西構成了一種樸素但高效的個人資料管理方式。

問題是，隨着產品越來越複雜，我想要的那部分體驗反而被包在了越來越厚的外殼裏。

---

### 臃腫、封閉和遷移焦慮

對個人用戶來說，筆記軟件最可怕的事情不是少一個按鈕，而是數據被困住。

當一個產品變得越來越重，商業化和附加功能越來越多，性能、內存佔用和日常響應速度開始讓人分心時，你自然會開始想：如果有一天我想離開，我能不能體面地把自己的內容帶走？

這個問題並不總是有舒服的答案。

筆記裏通常有多年資料、圖片、附件、剪藏、碎片想法和未完成的計劃。它們不是一批普通文件，而是一個人的知識軌跡。遷移如果依賴不穩定的第三方插件，或者只能導出到不夠開放、不夠容易二次處理的格式，用戶就會一直處在一種隱形的焦慮裏。

更進一步，AI Agent 正在成爲新的工作入口。今天我們已經可以讓 Codex、Claude Code、Cursor、Antigravity 這類工具幫我們寫代碼、整理資料、處理重複任務。那筆記系統也應該能被這些工具安全、清晰地訪問。

如果我的知識庫不能通過 API 或 MCP 被授權讀取、整理、歸檔、打標籤，它就很難進入下一代工作流。

---

### 輕量替代品很好，但我仍然想要三欄體驗

我也看過一些更輕量、更開放的筆記產品。它們通常很乾淨，也更接近開發者喜歡的形態。

但對我來說，還有一個缺口：經典印象筆記式的三欄體驗依然很重要。

三欄不是懷舊。它是一種高效的信息密度：

- 左側讓我知道內容放在哪裏
- 中間讓我快速掃過一組筆記
- 右側讓我立即進入編輯狀態

這種佈局尤其適合長期積累的資料庫。它不強迫我先進入某個複雜空間，也不要求我爲了管理內容先設計一套系統。它更像一個工作臺：打開就能用，東西都在手邊。

所以 EdgeEver 一開始就不是想做一個“全新範式”的筆記軟件。它想填補的是一個更具體的空白：保留熟悉、直接的三欄筆記體驗，同時把底層數據、部署方式和 Agent 能力打開。

---

### 爲什麼選擇 Cloudflare-native 自託管

我希望 EdgeEver 是普通個人也能長期使用的自託管產品。

傳統自託管常常意味着服務器、數據庫、對象存儲、備份、運維和賬單。對很多人來說，這些門檻會把“擁有自己的數據”變成一句好聽但很難堅持的話。

Cloudflare 的 D1、R2、Workers 和 Pages 給了一個很適合個人知識庫的組合：

- D1 存儲結構化數據和筆記內容
- R2 存儲圖片與附件
- Workers 提供 API
- 靜態前端可以部署在邊緣網絡上

在個人使用規模下，這套組合有機會做到接近零成本。更重要的是，它不需要用戶長期維護一臺服務器。你 Fork 倉庫、配置資源、部署，之後同步上游更新再重新部署，就能持續使用。

這就是 EdgeEver 想表達的一個價值：自託管不應該只屬於願意長期運維服務器的人。

---

### 開放數據是底線，不是賣點

EdgeEver 的內容模型從一開始就儘量保持清楚：

```text
content_json      TipTap/ProseMirror 文檔，編輯器權威格式
content_markdown  API、Agent、導入導出使用
content_text      搜索、摘要和索引使用
```

這樣做並不是爲了顯得技術上覆雜，而是爲了避免把所有場景都塞進一種格式裏。

編輯器需要結構化文檔，API 和遷移需要 Markdown，搜索需要純文本。每一種形態都有自己的用途。數據越清楚，未來遷移、備份、自動化和二次開發就越輕鬆。

我希望用戶使用 EdgeEver 時，有一種非常明確的安全感：這些內容是你的。你可以通過 REST API 讀取它，可以通過 MCP 交給 Agent 整理它，也可以在需要時把它遷移出去。

---

### MCP 讓筆記重新變成可行動的知識

AI Agent 友好是 EdgeEver 很重要的一部分。

過去，筆記軟件更多是在幫我們“保存信息”。但現在，僅僅保存已經不夠了。我們還希望工具能幫我們：

- 總結一批隨機記錄的想法
- 給舊筆記自動補標籤
- 從長期記錄裏整理項目脈絡
- 根據筆記內容生成待辦、文檔或方案
- 在遷移資料時自動清洗格式和層級

這些事情如果只能靠複製粘貼，就很快會變得笨重。MCP 的意義在於，用戶可以明確授權 AI Agent 訪問自己的 EdgeEver 實例，讓它在邊界清楚的前提下讀取和整理筆記。

這也是我想做 EdgeEver 的原因之一：筆記不應該只是沉睡的資料倉庫，它應該能進入自動化工作流，變成可以被調用、被組織、被重新使用的知識。

---

### EdgeEver 想成爲什麼

EdgeEver 不想成爲一個包辦一切的超級應用。

它更像一個開放、輕量、可長期擁有的個人筆記底座：

- 保留經典三欄體驗
- 支持富文本、圖片、嵌套筆記本和歷史版本
- 可以部署在 Cloudflare 上
- 數據模型清晰，支持 REST API、OpenAPI 和 MCP
- 對個人用戶儘量低成本
- 對 AI Agent 足夠友好

如果你懷念印象筆記早期那種直接、穩定、可依賴的工作臺，又希望今天的筆記系統能夠開放、自託管、能接入 AI Agent，那麼 EdgeEver 就是在爲這個交叉點而做。

我做它，是因爲我想要這樣一個工具：熟悉但不封閉，輕量但不簡陋，個人可擁有，又能面向未來的自動化工作流。

這就是 EdgeEver 的起點。
